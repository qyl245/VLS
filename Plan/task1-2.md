## 步骤一：关键点映射与坐标系构造

MediaPipe 33 关键点里，健身评估只需要躯干和四肢关节。先建一张映射表（参考 SiTrEx 表 4 和 AIFit 的关节定义）：

| 关节      | MediaPipe 索引（左/右） |
| --------- | ----------------------- |
| 肩        | 11 / 12                 |
| 肘        | 13 / 14                 |
| 腕        | 15 / 16                 |
| 髋        | 23 / 24                 |
| 膝        | 25 / 26                 |
| 踝        | 27 / 28                 |
| 足跟/足尖 | 29/31、30/32            |
| 脊柱参考  | 肩中点、髋中点          |

**身体坐标系构造**（SiTrEx §3.3 的方法，保证对全局旋转不变）：

1. 肩中点 `s`、髋中点 `h`，躯干向量 `y = h - s`（向上）
2. 左右肩连线 `x = shoulder_right - shoulder_left`（向右）
3. `z = x × y`（向前）
4. 归一化 `x, y, z`

这个坐标系是后续所有角度计算的基准，也直接对应未来 IMU 的躯干四元数——**接口一致性**。

## 步骤二：角度特征计算

按 AIFit §4.2 + SiTrEx §3.3 + BioCoach 的 46 维欧拉角思路，先实现 **V0 最小集**（约 15–20 个角度），覆盖深蹲、俯卧撑、弯举、弓步、平板：

**A. 关节屈曲角（向量夹角，10 个）**
肩、肘、腕、髋、膝，左右各一。公式同 SiTrEx Eq.13：

```
angle(j) = arccos( (j1-j)·(j2-j) / (||j1-j|| ||j2-j||) )
```

其中 j 是关节，j1/j2 是相邻关节。

**B. 躯干姿态（2 个）**

- 躯干屈曲：躯干向量 `y` 与重力方向（髋中点指向踝中点）的夹角
- 脊柱稳定性：躯干向量在窗口内的方差（后续评估表用）

**C. 解剖面投影角（6–8 个）**
按 SiTrEx 的平面投影法：

- 膝外翻指标：髋-膝-踝投影到冠状面后的夹角（深蹲关键）
- 踝背屈：小腿向量投影到矢状面后与 `y` 的夹角
- 肩外展（冠状面）、肩水平外展（横断面）、肩伸展（矢状面），左右各一
- 髋屈曲的矢状面投影角

**D. 对称性（3 个派生量）**

- 左右膝角差、左右腕高差、左右髋角差

**每个角度输出**：`{frame_id, joint, angle, confidence}`，confidence 取参与计算的 3 个关键点 visibility 的最小值。**这是未来 IMU 融合时加权融合的依据**。

---

## 步骤三：平滑与异常处理

参考 OffiStretch 和 Hu et al. 2026 的做法：

- 对每个角度序列做 **Savitzky-Golay 滤波**（窗口 5–9，多项式阶 2），抑制 MediaPipe 抖动。
- 对 `visibility < 0.5` 的帧，角度标为 `NaN` 并记录，**不插值**（避免伪造数据）；后续分割/评估时按缺失处理。
- 检测并剔除**角度跳变 > 30°/帧**的异常点（快速运动或误检），记录数量。

## 步骤四：可视化验证

对 3–5 个 QevD 视频，每个动作画 2–3 条关键角度曲线，对照 AIFit 图 4 的样式：

- 深蹲：膝屈曲 + 躯干屈曲（应看到周期性、底部峰值）
- 侧平举：左右肩外展（应看到相位同步）
- 平板：躯干屈曲 + 脊柱方差（应看到平稳）

**验收标准**：曲线肉眼可见周期性、左右对称动作的相位差合理、无明显毛刺。这步不做定量指标，只做 sanity check——定量留给任务 2.1 的分割 IoU。

## 步骤五：批量输出与格式定版

对任务 1.2 的 3–5 个视频批量跑，输出：

```
{dataset}/{video_id}/
  ├── landmarks.json        （任务1.2 已有）
  ├── angles.csv            （frame, joint, angle, confidence）
  ├── angles_wide.csv       （frame × 角度列，便于后续建模）
  └── meta.json             （fps、降采样、NaN 比例、异常点数量）
```

**接口预留**：

- `angles.csv` 里每行带 `source: "vision"`，未来 IMU 角度作为同结构行追加。
- 角度命名用统一词表（如 `left_knee_flexion`、`right_shoulder_abduction_coronal`、`torso_flexion`），与评估表 schema 的 `joint + feature` 字段一一对应。

## 一个关键决策点

**是否同时输出“身体坐标系下的 3D 关键点”**？建议输出——因为：

- BioCoach 的 DoF 选择和关节 attention 需要 3D 坐标，不只是角度；
- 未来 IMU 融合时，可以直接在身体坐标系下做四元数对齐，比重新构造坐标系稳定。

在 `landmarks.json` 旁加一个 `landmarks_body_frame.json`，存归一化到身体坐标系的 33×3 坐标。这不算额外工作，但为周 3 以后的模块省很多事。

## 风险与应对

| 风险                                   | 应对                                                    |
| -------------------------------------- | ------------------------------------------------------- |
| MediaPipe 世界坐标精度不足，角度噪声大 | 加大平滑窗口；或周 3 换 RTMPose 2D + 时序提升 3D 做对照 |
| 深蹲/弓步侧面视角下髋膝角被遮挡        | 记录 NaN 比例；这正好是未来 IMU 补位的论证素材          |
| QevD 视频视角不统一                    | 按动作筛选视角合适的片段；记录视角标签                  |
