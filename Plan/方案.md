## 一、系统总体架构（V0）

```
视频流 → ① 姿态与形状估计 → ② 动作分段与动作识别 → ③ 结构化评估表 → ④ 反馈生成与择时 → ⑤ 可视化/语言输出
                                    ↑
                          视觉推断的“传感级”特征（CoP近似、对称性、节奏、稳定性）
```

五个模块，每个模块都对应前面文献里可复用的具体方法。

---

## 二、模块级整合方案

### 模块 ①：姿态与形状估计

**目标**：拿到逐帧 3D 姿态 + 体型参数，作为后续所有特征的基础。

**方案（按优先级）**：

| 选项               | 方法                                                    | 适用场景           | 参考                                     |
| ------------------ | ------------------------------------------------------- | ------------------ | ---------------------------------------- |
| A（推荐起步）      | MediaPipe Pose Landmarker（33 关键点，含 3D）           | 端侧实时、简易硬件 | SiTrEx、OffiStretch                      |
| B（精度升级）      | RTMPose/HRNet 2D + 时序提升到 3D，或 MubyNet 微调 Fit3D | 需要更高角度精度   | AIFit 表 1（MubyNet-MV-FT MPJPE 35.7mm） |
| C（形状/生物力学） | HSMRI/SKEL 输出 46 维欧拉角 + SMPL 体型参数             | 需要个体形态测量   | BioCoach                                 |

**V0 建议**：**A 起步，B 做对照**。MediaPipe 足够跑通闭环，且 SiTrEx 实测 MoveNet-INT8 + AS 在 L=100–300 时 33–41ms（25–30 FPS），证明端侧可行。同时用 B 在 Fit3D 上验证角度精度对下游反馈的影响，作为消融。

**接口预留**：姿态模块输出统一为 `{frame_id, joints[K][3], confidence[K], body_shape（可选）}`，后续接 IMU 时只需在 joints 上融合四元数，不改下游。

---

### 模块 ②：动作分段与动作识别

**目标**：把连续视频切成单次重复，并识别当前动作类型。

**方案**：

- **重复分割**：直接用 AIFit 的两阶段法（自相关找周期 τ* + 约束优化细化起始点）。Fit3D 有 2,964 个重复时间戳可训练/验证，表 2 显示姿态质量足够时 IoU 0.730 vs GT 0.731。
- **动作识别**：用 QevD-Fit-300K 预训练一个轻量时序分类器（1D-TCN 或 Transformer），输入是角度序列而非原始关键点。SiTrEx 的 AU 模型也可复用——它不需要动作标签就能判断“哪些角度重要”，可先于分类器运行。
- **错误/变体识别**：用 QevD-Fit-300K 的 148 动作变体（含常见错误）训练一个多分类器，输出“正确/错误类型”。IMCD 的三分指标（M1 二分类 F1、M2 高置信错误 F1、M3 低置信错误占比）用于评估。

**V0 建议**：**AIFit 分割 + 角度序列分类器**。分割用无监督方法（不需要训练），动作识别用 QevD 微调。先支持 3–5 个核心动作（深蹲、俯卧撑、哑铃弯举、弓步、平板支撑），覆盖上/下肢、动态/静态。

**接口预留**：输出 `{rep_id, start_frame, end_frame, exercise_label, variant_label, confidence}`。后续加 IMU 时，重复分割可融合角速度峰值检测，提高遮挡下的鲁棒性。

### 模块 ③：结构化评估表（核心创新点）

这是你区别于纯 VLM 的关键，也是未来接传感的“容器”。

**3.1 视觉推断的“传感级”特征**

在 AIFit 角度特征基础上，显式定义一组具有物理语义的量，并标注置信度：

| 特征              | 计算方法                           | 物理对应            | 置信度来源                        |
| ----------------- | ---------------------------------- | ------------------- | --------------------------------- |
| 关节角度序列      | 膝/髋/肘/肩/脊柱                   | IMU 关节角          | 姿态 confidence                   |
| 角速度/角加速度   | 角度一阶/二阶差分                  | IMU 陀螺仪          | 差分噪声估计                      |
| 左右对称性        | 左右膝角差、左右腕高差             | 双侧 IMU 对比       | 双侧 confidence 最小值            |
| 躯干稳定性        | 脊柱角方差、质心轨迹抖动           | 腰部 IMU 加速度方差 | 姿态抖动 + confidence             |
| 动作节奏          | rep 周期、节奏一致性               | 角速度峰值间隔      | 分割 IoU                          |
| 近似 CoP/重心投影 | 3D 脚位置 + 躯干质心，投影到支撑面 | 足底压力中心        | 需相机标定 + 地面平面，标为低置信 |
| 动作幅度（ROM）   | 关节角最大-最小                    | IMU 角度范围        | 姿态 confidence                   |

**关键设计**：每个特征带 `{value, confidence, source: "vision"}`。未来 IMU/EMG 进来时，同一张表里加 `{value, confidence, source: "imu"/"emg"}`，融合规则按 confidence 加权或规则优先级。

**3.2 评估规则（两阶段）**

- **阶段一：教练参考签名对比**（AIFit 风格）。教练录一段标准动作，提取角度特征 → 主动/被动特征划分（可用 SiTrEx AU 模型替代能量二分）→ 统计签名（max/min/correlation/mean/std）。学员逐 rep 对比，阈值判定偏差方向与程度。阈值由全局 critic 参数 δ 缩放（AIFit §4.3），适配初学者/进阶者。
- **阶段二：错误分类器**（QevD/IMCD 风格）。用 QevD-Fit-300K 微调的多分类器输出错误类型（如“膝盖内扣”“蹲得不够低”），与阶段一的连续偏差互补。IMCD 三分指标评估可靠性。

**3.3 输出格式（结构化评估表）**

```json
{
  "rep_id": 3,
  "exercise": "squat",
  "phase": "bottom",
  "assessments": [
    {"joint": "left_knee", "feature": "flexion", "value": 85, "ref": 95, "deviation": -10, "severity": "medium", "confidence": 0.82, "source": "vision"},
    {"joint": "spine", "feature": "stability", "value": 0.04, "ref": 0.02, "deviation": "high_variance", "severity": "high", "confidence": 0.61, "source": "vision"}
  ],
  "symmetry": {"knee_angle_diff": 12, "severity": "medium", "confidence": 0.75},
  "rhythm": {"rep_duration": 2.1, "consistency": 0.68, "severity": "low"}
}
```

**接口预留**：表里预留 `source` 和 `confidence` 字段；未来加 `"emg_activation": {"left_vmo": 0.4, "right_vmo": 0.7}` 这类条目，融合逻辑不改。

### 模块 ④：反馈生成与择时

**方案：模板 + LLM 混合，规则触发择时。**

- **择时**：借鉴 STREAM-VLM 的 `<next>`/`<feedback>` 思路，但 V0 不用端到端训练，而是**规则触发**：
  - 错误严重度 ≥ medium 且持续 ≥ N 帧 → 触发纠正反馈；
  - 每个 rep 结束 → 触发总结反馈；
  - 静默期 ≥ 5 秒且动作正确 → 触发鼓励反馈（参考 QevD 的平均静默期 5.2s）。
  - 这比端到端 `<feedback>` token 简单可控，且 OffiStretch 的教训（反馈过多造成压力）提醒要控制频率。
- **说什么**：
  - **模板路线**（AIFit 主动/被动语法）：安全、零幻觉，覆盖常见错误。作为 fallback。
  - **LLM 路线**（BioCoach 风格）：把结构化评估表 + 个体形态（可选）+ 历史反馈转成 prompt，喂给 LLaMA-2-7B/LLaVA 类模型生成自然语言。参考 BioCoach 的 prompt 格式：

    ```
    Current pose: right knee 85°, left knee 88°, hip 75°
    Form issues: Right knee flexion insufficient (85° detected, 90° required)
    ```

    输出要求：量化、解剖精确、相位感知、不重复历史。
  - **混合策略**：LLM 生成 + 规则校验（数值是否与评估表一致、是否提到不存在的关节）。校验失败回退模板。

**V0 建议**：**先模板，后 LLM**。模板跑通闭环和评估，LLM 作为增强版对比。BioCoach 的 QEVD-bio-fit-coach 和 LLM-Bio-Acc 指标可直接用于评估你的 LLM 版本。

### 模块 ⑤：可视化与输出

- **健身镜界面**（参考 FitSight 图 1）：性能条（0–100%）、反馈文字、重复计数、目标追踪。
- **姿态叠加**（参考 OffiStretch 图 3）：圆圈大小表示角度误差，线条箭头表示距离/方向误差；错误关节高亮。
- **纠正后姿态**（可选，参考 Zhao et al.）：用简化版——只显示教练参考姿态的骨架叠加，不做完整序列纠正。
- **语音**：TTS 播报反馈，参考 OffiStretch 每 5 秒音频反馈。

| 模块     | 训练/验证数据                                                          | 用途                                  |
| -------- | ---------------------------------------------------------------------- | ------------------------------------- |
| 姿态估计 | Fit3D（MOCAP 真值）、M3GYM                                             | 微调/验证 3D 姿态精度                 |
| 重复分割 | Fit3D（2,964 时间戳）                                                  | 训练/验证分割 IoU                     |
| 动作识别 | QevD-Fit-300K（148 动作变体）                                          | 微调时序分类器                        |
| 错误分类 | QevD-Fit-300K、IMCD                                                    | 微调错误多分类器；三分指标评估        |
| 反馈生成 | QevD-Fit-COACH（长视频实时反馈）、QEVD-bio-fit-coach（生物力学精确版） | LLM 微调/评估；T-F-Score、LLM-Bio-Acc |

**自采**：V0 阶段建议小规模自采 3–5 人 × 3–5 动作，用手机拍摄，人工标注“正确/错误类型”和“反馈是否恰当”，用于端到端用户研究。不需要 IMU/EMG。

## 四、评估方案（按 ERS 五条设计）

**自动指标**：

- 重复分割 IoU（Fit3D 协议）。
- 动作识别/错误分类：Accuracy、F1、IMCD 三分指标 M1/M2/M3。
- 反馈质量：METEOR、ROUGE-L、BERTScore、LLM-Acc（QEVD 协议，3 秒窗口匹配）、T-F-Score（何时说）、LLM-Bio-Acc（BioCoach 协议）。
- **新增：评估表一致性**——LLM 生成的反馈中提到的关节/方向/数值，与结构化评估表的一致率（规则校验）。

**人工评估**：

- 专家评分：物理治疗师/教练对反馈的解剖正确性、安全性、可操作性打 1–5 分，报告 Cohen Kappa/ICC（ERS 要求）。
- 用户研究：分层（beginner/intermediate），对比 V0 vs 纯视频指导 vs 人工教练，指标包括动作 MAE（参考 Hu et al. 2026 的关节角 MAE）、调节效能感、动机、偏好（参考 OffiStretch 的 forced-choice）。
- **错误反馈专项**：统计系统“说错”或“不该说却说”的比例（Heliyon 综述指出的空白）。

**消融**：

- 姿态质量：MediaPipe vs RTMPose/微调 MubyNet → 对反馈准确率的影响（参考 AIFit 图 7 的 critic threshold 分析）。
- 评估表：纯角度 vs 角度+对称性+稳定性+节奏 → 反馈质量增量。
- 反馈生成：模板 vs LLM vs 混合 → 语言质量 vs 安全性。
- 择时：固定间隔 vs 规则触发 → T-F-Score 与用户主观压力。

## 五、V0 到 VLS 的迭代接口

V0 的每个模块都为传感预留了接口：

1. **姿态模块**：输出格式含 `confidence` 和 `source`，IMU 四元数可直接融合到 joints。
2. **评估表**：每条 assessment 有 `source` 和 `confidence`，EMG 激活、IMU 角速度作为新条目加入，融合规则按 confidence 加权。
3. **反馈生成**：prompt 里预留“传感证据”字段，未来加 `"emg": "left VMO activation 40% lower than right"`。
4. **评估**：V0 的视觉-only 结果作为 VLS 增量对比的基线（参考 BioCoach 把 Stream-VLM 作为强基线）。

**V1 增量验证计划**（简要）：

- 小规模自采：摄像头 + 2–3 个消费级 IMU（手机/手表）+ 1–2 通道 EMG（MyoWare），3–5 人 × 2–3 动作。
- 验证两件事：(a) 视觉推断的传感量（CoP 近似、对称性、节奏）与真实 IMU/EMG 的相关性；(b) 加入真实传感后，反馈质量（专家评分 + LLM-Bio-Acc）是否显著提升。
- 用 FLEX 做大规模视觉+EMG 验证（需先确认其 IMU 是否齐全）。
